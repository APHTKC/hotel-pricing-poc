# APH 私人房價情境分析（第 03 區）

## 定位

第 01「即時總覽」與第 02「歷史房價分析」只處理公開市場資料。第 03
區用於比較市場觀測值與 APH 未來房價假設，屬於 PHT 內部決策工具，不是
公開儀表板的延伸頁面。

在存取控制完成前，不得將第 03 區的頁面、API、試算表、假設值或衍生報表
放進 `public/`、GitHub Pages artifact 或任何可公開下載的 JSON。

## 上線門檻

以下條件全部成立後才開始製作可用版本：

1. 官方來源已有足夠歷史期間，且主要競爭飯店的每日資料取得穩定。
2. 至少一個正式授權的 OTA 來源可穩定取得資料。
3. 已完成跨來源去重，並統一含稅總價、入住人數、晚數、早餐與取消條件。
4. 已決定使用伺服器端登入或身分代理；不得使用純前端密碼或把密碼寫入
   JavaScript。
5. 已建立允許使用者名單、存取紀錄、備份及資料刪除方式。

## 存取與部署原則

- 公開 GitHub Pages 繼續只放第 01、02 區。
- 第 03 區使用不同的部署目標與網址，所有 HTML、API 與資料請求都必須先
  通過身分驗證。
- 優先評估公司 Google Workspace SSO；若管理政策不允許，再評估具身分代理
  能力的獨立服務。
- 未登入者不得取得頁面內容、JSON、匯出檔或可推導假設值的錯誤訊息。
- 不在公開網站顯示第 03 區連結，直到私人環境正式可用。

## 資料隔離

公開觀測資料與內部假設不得寫入同一份公開資料檔。

### 公開市場觀測

- `observation_id`
- 飯店、城市、行政區、房型與面積
- 查價日、入住日、提前訂房天數
- 來源平台與來源房源代碼
- 未稅價、服務費、稅、含稅總價與幣別
- 早餐與取消條件

### 私人 APH 假設

- `scenario_id`、版本與狀態（草稿／核准／封存）
- 建立者、建立時間與最後修改時間
- 適用期間、星期別、季節與特殊日標籤
- 房型、房型面積與可比較房型群組
- 提前訂房區間
- 假設房價、幣別、稅費口徑與備註
- 使用的競爭飯店群組及市場資料快照版本

市場觀測只能被私人分析讀取；私人假設不得反向輸出到公開儀表板或公開匯出。

## 預計分析功能

- APH 假設價與市場平均、中位數、四分位數及指定百分位比較。
- 依日期、平假日、季節、房型面積、提前訂房天數與來源平台篩選。
- 以可自訂的面積容許範圍建立相近房型群組，例如讓 APH 與 55㎡ 房型落入
  同一個比較群組。
- 儲存多個情境（基準、保守、積極），但不自動覆寫先前版本。
- 顯示樣本數、資料完整度與來源分布，避免把稀疏樣本當成可靠市場價格。
- 匯出時加上「內部資料」標記、產生時間與情境版本。

## 第一階段不做

- 不用公開頁面的 JavaScript 密碼保護內部資料。
- 不在資料不足時提供單一「建議售價」。
- 不把 OTA 與官網看似相同、但條件不同的價格直接視為重複資料。
- 不把 APH 假設混入現有平均房價、中位 ADR 或歷史趨勢。
- 不儲存真實姓名、個人資料、付款資訊或訂房人的任何資料。

## OTA 準備完成的判定

第 03 區開發前，以最近 30 天為檢查期間：

- 核心競爭飯店至少 70% 的查價日有可比較價格。
- 每個比較樣本都能辨識來源、總價口徑、入住人數、晚數與取消／早餐條件。
- 跨來源重複率與無法配對率都有可追蹤報表。
- 至少能用一組固定條件重現相同的市場比較結果。

達到門檻後，先以不含真實 APH 假設的測試資料完成私人原型與權限測試，再由
PHT 決定何時輸入實際情境。
